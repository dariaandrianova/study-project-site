# Правила работы над сайтом

## Обязательные требования пользователя

- Не добавлять лишние декоративные элементы.
- Не использовать постоянное движение или бесконечные анимации.
- Предусмотреть `:focus-visible` для клавиатурной навигации.
- Учитывать `prefers-reduced-motion`.
- Использовать семантическую HTML-разметку.
- Не устанавливать дополнительные библиотеки, если задача решается существующими средствами.
- Не менять глобальные стили сайта без необходимости.
- Простая структура: HTML, CSS, JavaScript и отдельные папки для ресурсов. Понятные имена классов и комментарии на русском, обозначающие разделы в HTML, CSS и JS. Инструкция по запуску и самостоятельному редактированию.
- Макеты приложения самостоятельны: не менять их оформление.
- Неинтерактивные группы тегов закреплять у нижнего внутреннего края модулей, сохраняя отступ от текста. Исключение — метки возле заголовков (`hypotheses-directions__count` или `tags--inline`). Не путать теги `.tags` с навигационными табами `.research-tab`; структуру и поведение табов при правках тегов не менять.

- В исследованиях нумеровать только ключевые внешние модули и подробные данные в модальных окнах (этапы, вопросы, гипотезы). Не нумеровать внутренние карточки, инсайты, наблюдения, смысловые группы и короткие тезисы. Исключение — самостоятельный пошаговый процесс, где важна последовательность. При локальных правках не менять содержимое других табов; нумерацию в модальных окнах сохранять.

- Кнопки открытия модальных окон внутри модулей оформлять единообразно: текст + SVG `arrow-up-right`, без рамки и фоновой подложки (`modal-action-button`), с видимым `focus-visible` и областью нажатия не менее 44 px. Располагать внизу модуля над внутренним отступом, под тонким разделителем (`tile--modal-action`, `modal-action-footer` с `margin-top: auto`). Сохранять JS-классы и ARIA-связи с диалогами.

## Визуальное направление

- Сайт-кейс командного проекта в рамках повышения квалификации.
- Мягкая, спокойная, профессиональная подача; модульная сетка из плиток со скруглениями.
- Умеренное количество воздуха, без излишней плотности и огромных пустых пространств.
- Белая основа, серые поверхности, чёрный/почти чёрный текст. Один-два приглушённых акцента с читаемым контрастом; конкретные цвета пока не выбраны.
- Без гигантской типографики. Локальный Unbounded для h1–h2, локальный Manrope для остального текста.
- Ограниченное число размеров и начертаний. Подписи — 14 px на desktop, 13 px на tablet/mobile; основной текст — 16 px; заголовки модулей — 20 px. Подробные адаптивные значения зафиксированы ниже. Преимущественно Regular/Medium, Bold по необходимости.
- Размеры и отступы на базе шага 4 px; 2 px для мелочей, 14 px — разрешённое исключение для подписей.
- Расстояния отражают смысловую группировку и вложенность: между связанными элементами они меньше или равны расстояниям до других групп. Скругления вложенных элементов меньше внешних (пример: модуль 20 px, кнопка 16 px).
- Плавные переходы и состояния normal/hover/active/focus-visible. Особые эффекты обсуждать отдельно.
- Дополнительные сведения могут открываться по клику; конкретный способ выбирать при проектировании блока.
- Первый экран должен объяснять контекст повышения квалификации, идею, курс и основные требования. Итоговая структура содержания ещё обсуждается пользователем в GPT.

## Отступы и визуальная группировка

- Отдельное правило модулей: между соседними модулями одной композиции всегда 20 px по горизонтали и вертикали (`--space-module`). Это осознанное исключение из общей иерархии для визуального единства. Не уменьшать вслед за ним padding карточек, расстояния внутри контента и отступы от заголовков разделов до содержимого.

- Применять на всём сайте, включая содержимое всех модальных окон, и на всех адаптивных размерах: чем теснее смысловая связь, тем меньше расстояние. Контент карточки должен восприниматься как единая группа.
- Внутри группы использовать минимальные отступы; между смысловыми группами — увеличенные; между самостоятельными карточками и модулями — единообразные согласно дизайн-системе.
- Ориентиры: заголовок → описание 8–12 px; элементы одной группы 12–16 px; смысловые группы 24–32 px; между модулями одной композиции — строго 20 px по отдельному правилу. Адаптировать значения под существующую сетку и масштаб компонента, сохраняя шаг 4 px.
- Не разрывать связанные элементы чрезмерными внутренними отступами и не сливать самостоятельные блоки слишком тесными внешними расстояниями. Сохранять единый ритм на desktop, tablet и mobile.
- Правило относится к расстояниям между элементами и группами, а не механически к padding контейнеров: отступ содержимого от границы карточки может быть больше расстояния до соседней карточки, если этого требует композиция.
- В модальных окнах различать расстояния внутри пункта (например, название → пояснение), между отдельными пунктами и между крупными подразделами; не задавать им одинаковые отступы. Заголовки таблиц не разрывать внутри слова: подбирать ширину колонки, сохраняя мобильное представление.
- Делать группировку понятной через отступы, без дополнительных разделителей, рамок и фоновых подложек только ради разделения.

## Предложенные стартовые значения (можно уточнять)

- H1: 40 px; H2: 28 px; title: 20 px; основной текст: 16 px; caption: 14 px.
- Отступы: 4, 8, 12, 16, 24, 32, 48, 64 px.
- Между разделами: 48–64 px; между модулями одной композиции — 20 px на всех размерах экрана; поля модуля: 24–32 px; внутри групп: 8–16 px.
- Общие параметры хранить в CSS-переменных для удобного редактирования.

### Шрифты и начертания

- H1/H2 и отдельные существующие числовые акценты — локальный `Unbounded`; остальной текст — локальный `Manrope`
- Сохранять существующие начертания: H1 600, H2 500, заголовки модулей 600; их не менять автоматически при изменении ширины
- Сохранять характерный letter-spacing: H1/H2 −0.04em, H3 −0.02em. Не масштабировать обычный текст через `transform: scale()`
- Семантический HTML-уровень не всегда равен размеру: лейблы внутренних групп и подписи могут оставаться меньше, а Event First использует акцентную H2-роль внутри H3

### Межстрочные интервалы

- Desktop сохраняет существующие значения: H1 1.28, H2 1.4, H3 1.4, основной текст 1.6; акцентный H2 команды 1.3; подписи Hero 20 px и заголовки карточек Hero 28 px сохранены как существующие исключения
- Tablet/mobile: H1 1.15; H2 и акцентный H2 команды 1.2; H3/H4 1.3; основной и подробный текст 1.55; подписи и метаданные 1.4; крупные числовые акценты 1.2
- Адаптивные line-height задавать без единиц измерения, по роли текста; не уравнивать заголовки, подписи и абзацы
- В прототипах и экспортированных SVG приложения собственная типографика: её не изменять. Размеры изображений и видео сохранять

### Переносы

- На desktop сохранять намеренные переносы заголовков. В HTML использовать пробел перед `<br class="heading-break">`; на mobile этот br скрывается, пробел сохраняет границу слов
- На всех разрешениях обычные слова переносятся только целиком: `hyphens: none`, `-webkit-hyphens: none`, `word-break: normal`, `overflow-wrap: normal`. На tablet/mobile у заголовков сохраняется `text-wrap: pretty`. Автоматические переносы по слогам и аварийное разбиение обычных слов запрещены
- Не задавать nowrap заголовкам и абзацам. Существующие однострочные табы навигации остаются исключением: они прокручиваются горизонтально
- Сохранять действующую функцию `SiteTypography`: &nbsp; в статическом HTML, U+00A0 в JS; короткие предлоги, союзы и частицы связывать по правилам проекта, не создавать длинные неразрывные цепочки
- Не менять формулировки ради помещения в карточку. Точки внутри предложений сохранять, завершающую точку короткого блока убирать по общим правилам
- При новых текстах проверять ширины 1440, 1024, 768, 430, 390, 375 и 320 px, включая скрываемые табы, диалоги и popover. Не исправлять переполнение уменьшением основного текста ниже 16 px

Изменения типографики не должны менять колонки, порядок модулей, padding/gap, цвета, скругления, размеры медиа или анимации. Естественное изменение высоты текста при переносах допустимо.

## Переносы только целыми словами — дополнение от 04.11.2026

- На desktop, tablet и mobile для обычного текста обязательны `hyphens: none; -webkit-hyphens: none; word-break: normal; overflow-wrap: normal`
- Если слово не помещается в конце строки, переносить его целиком на следующую. Не использовать автоматические словарные переносы, break-all, anywhere и break-word для обычного текста
- Не вставлять дефисы, мягкие переносы (HTML-сущность shy / символ U+00AD) или br внутри слова ради вёрстки. Смысловые дефисы в словах сохранять
- Если отдельное слово шире контейнера, сначала пересмотреть доступную ширину, padding и адаптивную компоновку. Не обрезать текст и не уменьшать автоматически шрифт
- Для явно отмеченных длинных URL, технических идентификаторов и непрерывных строк допускается класс `.text-breakable` с `overflow-wrap: anywhere`. Он не предназначен для заголовков и обычных описаний
- Правило действует также для всех диалогов, popover, подписей, тегов и будущего динамического текста. Неразрывные пробелы по существующим правилам сохранять, избегая чрезмерно длинных цепочек

- Если заголовку «Исследовательские гипотезы» не хватает ширины в мобильном диалоге, он занимает полную строку под X; размер шрифта сохраняется

## Неразрывный дефис после «по-» — 08.11.2026

- Слова с приставкой «по-» переносить только целиком: «по‑новому», «по‑другому», «по‑человечески». Запрещён перенос после «по-»
- Использовать неразрывный дефис U+2011: в статическом HTML `&#8209;`, в JavaScript `\u2011`. Внешний вид слова и смысл сохраняются, дополнительные дефисы не добавлять
- Оба форматтера `SiteTypography` автоматически заменяют обычный дефис после начального «по» перед кириллической буквой; правило действует на весь сайт, диалоги и будущий динамический текст
- Обрабатывать только текстовые узлы: не менять пути ресурсов, URL в атрибутах, HTML-разметку, SVG и код. Обычные слова по-прежнему не разрывать по слогам


## Системные ошибки и изображения — 08.11.2026

- `404.html` использует общие шрифты, токены, белый модуль и существующую `.modal-action-button`. Только «404», «Кажется, кто-то заблудился», «На главную ↗». Ссылка ведёт на `/`, без history.back. HTTP-статус неизвестного маршрута — 404, не 200
- Для локальной проверки маршрутов использовать `python3 serve.py 8000`. `serve.py` обслуживает существующие файлы, при неизвестном адресе возвращает `404.html`. На хостинге нужен обработчик custom 404; `_redirects` подготовлен для Netlify. Обычный `python3 -m http.server` не подключает пользовательскую 404
- Единый алерт — `SiteErrors.show(container, { retry })` из `js/errors.js`, стили `css/errors.css`. Тексты: «Ох, ёпт, чёт не получилось», «Попробуй ещё раз», кнопка «Попробовать ещё раз». Без отдельных вариантов в разделах
- Ошибки используют общий `--error` (#BC4141, существующий цвет отрицательного статуса) и производную светлую `--error-surface`. Полоска, предупреждение, текст и иконка повтора имеют один красный акцент; кнопка не фиолетовая и не насыщенно-красная
- Retry возвращает Promise, который разрешается только при реальном успехе. В процессе кнопка disabled и aria-busy=true, повторные нажатия заблокированы. Ошибка сохраняет алерт и возможность повторить; успех убирает алерт. Не перезагружать всю страницу, не запускать бесконечные повторы
- Для будущих операций можно использовать `SiteErrors.run(container, operation)`. Не отображать универсальный алерт без фактической ошибки. Текущее использование — загрузка видео; изображения используют компактное состояние того же семейства
- Алерт имеет role=alert, кнопка — клавиатурный focus-visible. При reduced-motion переходы отключены. На узком экране кнопка переносится под текст, размеры текста не уменьшать
- Осмысленные изображения получают краткий конкретный alt; фотографии — имя и участие в команде. Декоративные иллюстрации и иконки возле подписанных кнопок сохраняют alt="". У интерактивного родителя доступное название, не дублировать подписи без необходимости
- Резервировать геометрию изображений через корректные width/height и существующий CSS aspect-ratio. Не менять исходные файлы, пропорции, цвет или кадрирование ради ошибки
- При сбое `errors.js` оставляет изображение в потоке и для скринридера (opacity:0), перекрывает его область компактным fallback и кнопкой «Повторить». Alt не является единственным видимым сообщением
- Повтор загружает тот же исходный ресурс с новым ключом кэша. При неуспехе fallback сохраняется; при успехе удаляется. Кнопки повтора не вкладывать в ссылки и кнопки; маленьким иконкам — компактное состояние без больших текстовых плашек
- Обработчики изображений подключаются один раз, включая динамические материалы. Не создавать второй overlay и не менять механику существующих bottom sheet

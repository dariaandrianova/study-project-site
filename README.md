# Учебный проект — сайт-кейс

## Типографика текстов

Статические тексты редактируются в `index.html`: неразрывный пробел обозначается `&nbsp;`. В строках `js/script.js` используйте `\u00A0`. Финальная точка у короткого блока не ставится; точки между предложениями, вопросы и восклицания сохраняются.

`js/typography.js` автоматически обрабатывает текстовые узлы существующего и добавленного контента. Он не меняет ссылки, атрибуты, изображения или HTML-разметку. Короткие предлоги/союзы связываются со следующим словом; поддерживаются инициалы и числа с единицами. Новые связи ограничены тремя словами и 32 символами. Для точечного исключения можно поставить `data-typography="off"` на элемент. CSS и размеры не меняются.

Статический сайт на HTML, CSS и JavaScript. Без сборки, npm, внешних сервисов и библиотек. Все шрифты и изображения локальные.

## Как открыть

Распакуйте архив целиком и откройте `index.html` двойным кликом. Интернет не нужен. Не перемещайте HTML отдельно от папок `css`, `js` и `assets`.

Для локального сервера (необязательно): из папки сайта выполните `python3 serve.py 8000`, затем откройте `http://localhost:8000`. Остановка — Ctrl+C.

## Где менять карточки первого экрана

В начале `js/script.js` находится массив `heroCards`. Каждая карточка имеет:

- `title` — название;
- `description` — описание;
- `image` — путь к изображению относительно `index.html`;
- `href` — якорь раздела, например `#course`.

Положите новое изображение в `assets/images/` и замените значение `image`, например на `assets/images/course.jpg`. Все пять карточек сейчас используют одинаковую заглушку `placeholder.svg` (#EEEEEE, горы и солнце). Изображения заполняют карточку с обрезкой по краям (`object-fit: cover`). Для другого кадрирования можно задать `object-position` в CSS конкретной карточки.

## Как подключить якорь

Якоря уже работают: `#course`, `#research`, `#project`, `#team`, `#insights`. Для нового раздела задайте уникальный `id` в HTML и такой же `href` с символом # в массиве карточек:

```html
<section id="my-section" tabindex="-1" aria-labelledby="my-title">
  <h2 id="my-title">Название раздела</h2>
</section>
```

```js
href: '#my-section'
```

## Где менять оформление

В начале `css/styles.css` блок `02. ПАРАМЕТРЫ САЙТА`: цвета, шрифты, размеры, скругления и ширина страницы. Основная палитра нейтральная; приглушённый шалфейный и лавандовый — стартовое предложение для акцентов.

Положение карточек первого экрана — блок `05. HERO`, классы `.hero-card--1` … `.hero-card--5`. Они расположены свободно и перекрываются. При hover и фокусе карточка выравнивается, увеличивается и оказывается над соседними. На экранах до 1100 px карточки превращаются в горизонтальную ленту с видимыми подписями. На сенсорных устройствах подписи тоже видны сразу.

Комментарии в HTML, CSS и JS обозначают разделы. Поиск по названию раздела быстро приведёт к нужному коду.

## Содержание и статус

Hero выполнен по заданию. Остальные разделы — редактируемый черновик на основе FigJam и доступных сообщений проекта. Личная роль оставлена для заполнения; метрики описывают план оценки, а не результаты запущенного продукта. Место для макетов приложения отмечено заглушкой, сами макеты не изменены. Тексты курса и требований стоит сверить с финальными материалами перед публикацией.

## Доступность

Семантическая разметка, обычные ссылки, ссылка пропуска навигации, видимый фокус, управление раскрывающимися блоками с клавиатуры, подписи без hover на телефонах. При `prefers-reduced-motion` отключены переходы, масштабирование и плавная прокрутка. Бесконечных анимаций нет.

Карточки Hero имеют пропорцию `aspect-ratio: 5 / 4` на всех экранах. На узких экранах минимальная ширина карточки — 280 px; доступна горизонтальная прокрутка. Размеры и отступы заданы целыми значениями; адаптивная процентная ширина может вычисляться браузером в дробные пиксели.

Рекомендуемый размер изображений карточек: 1000 × 800 px или 1500 × 1200 px (5:4).

## Таб «Проверка гипотез» и матрица валидации

Четыре модуля редактируются в `index.html`, секция `research-panel-validation`. Итоговая командная проверка: 6 подтверждённых, 12 частично подтверждённых и 9 неподтверждённых гипотез. В ключевом акценте страницы показано «6 из 27 подтвердились» — только полностью подтверждённые гипотезы.

Единый источник всех 27 формулировок, категорий и итоговых статусов — `hypotheses` в `js/hypotheses-modal.js`. Поля: `id`, `text`, `category`, `validationStatus` (`confirmed`, `partial`, `rejected`), `validationSourceId` — номер в исходной FigJam-матрице для сверки. `validationReason` можно добавить только при наличии обоснования команды. Порядок FigJam и окна различается: соответствие проверено по содержанию, а не по совпадению номеров.

`js/validation-matrix.js` берёт формулировки и командные статусы из этого массива по `id`. Индивидуальные результаты хранятся отдельно: `validationRespondents` (`id`, `name`) и `validationMatrix` (`number`, `responses`). Добавляйте только реальные ответы: `{ respondentId, status, observation }`. Поддерживаются `confirmed`, `partial`, `rejected`, `no-data` и старое `unconfirmed` для совместимости. Итог команды выводится отдельной колонкой/строкой и не заменяет индивидуальные оценки.

На desktop окно показывает таблицу с внутренней горизонтальной прокруткой, на mobile — гипотезы, итоговый статус и отдельный список респондентов при наличии. Индивидуальные оценки пока отсутствуют; итоговые 27 статусов полностью заполнены. Для внесения личного ответа можно использовать `validationMatrix.find((row) => row.number === 1).responses.push(...)`, не меняя итог команды.

В табе «Проверка гипотез» верхние два модуля собраны в ряд 40/60, нижние — 60/40. На экранах 1024 px и меньше оба ряда перестраиваются в одну колонку. Иконки легенды встроены в HTML из `check-contained.svg`, `cancel-left.svg`, `x-circle-contained.svg`, их цвет задаёт `currentColor`. Прямые ссылки «Перейти к интервью», «Перейти к проверке гипотез» и «Перейти к Job Stories» удалены; навигация табов остаётся доступной.

## Горизонтальная навигация исследований

В `#research` 10 табов в одной строке, включая Tone of Voice после MVP. Метрики будут размещены отдельно от исследований. Белая общая капсула `.research-tabs__list` прокручивается горизонтально, scrollbar скрыт. Табы не сжимаются, названия не переносятся; размер шрифта сохранён 14 px. Default — графитовый текст, hover — фиолетовый без подложки, active — `#F0EDFF` с фиолетовым текстом и начертанием 600. `data-tab-label` резервирует ширину более плотного начертания и предотвращает скачки соседних вкладок.

При выборе таба в правой четверти он перемещается примерно к 28% ширины ленты; в левой четверти — к 72%, открывая соседние этапы. Центральный таб не вызывает лишней прокрутки. Программные переходы из контента центрируют вкладку, сохраняя существующую вертикальную прокрутку к панели. Все смещения ограничены реальной длиной ленты. Свайп и трекпад работают нативно, Shift + колесо прокручивает горизонтально; обычное вертикальное колесо не блокируется. `prefers-reduced-motion` отключает плавную прокрутку.

Оформление находится в `css/styles.css`; горизонтальное позиционирование — `revealSelectedTab` в `js/script.js`. Порядок и тексты кнопок редактируются в HTML; `data-tab-label` автоматически синхронизируется из подписи при инициализации. Содержимое Tone of Voice редактируется в `research-panel-tone-of-voice`. Анимация и содержимое прежних табов сохранены.

По краям ленты табов показывается мягкое белое затухание шириной 32 px только с той стороны, где есть скрытые вкладки. Состояние обновляется при ручной/автоматической прокрутке, изменении ширины и загрузке шрифтов. Градиент пропускает клики и свайпы; при достижении края или отсутствии переполнения исчезает.

### 404 и ошибки загрузки

`404.html` — готовая страница ошибки. Проверка: запустите `python3 serve.py 8000` и откройте `http://localhost:8000/неизвестная-страница`. Сервер вернёт HTTP 404; кнопка ведёт на `/`. Для реального хостинга включите custom 404 с этой страницей; для Netlify уже есть `_redirects`. При открытии HTML двойным кликом или через другой простой сервер перехват несуществующих маршрутов не работает автоматически.

Общий компонент ошибки находится в `js/errors.js`, стили — `css/errors.css`. Пример для будущего запроса:

```js
SiteErrors.run(container, async () => {
  const response = await fetch(url);
  if (!response.ok) throw new Error('Материал не загружен');
  const data = await response.json();
  render(data); // Обновить содержимое только после успеха
});
```

Для ручного показа после уже пойманной ошибки: `SiteErrors.show(container, { retry: loadMaterial })`. Функция повтора обязана вернуть Promise и отклонить его при сбое. Кнопка сама блокирует повторные нажатия и удаляет алерт после успеха. Для видео уже используется этот компонент.

Обработка `<img>` подключается автоматически. Сохраняйте width/height, существующий aspect-ratio и корректный alt: при ошибке место изображения остаётся в сетке, появляется локальный fallback с повтором именно этого ресурса. Декоративным иконкам оставляйте пустой alt. Правила также действуют для динамических изображений и материалов в шторках.

Резервная копия до изменений: `backups/before-error-handling/`.
